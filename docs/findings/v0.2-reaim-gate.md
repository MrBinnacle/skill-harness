# v0.2 re-aim — pre-registered entry gate

**Status:** gate document. The v0.2 build does NOT start until every field below is
filled and the named pending decision is real. This is the instrument-gating discipline
([why-naive-skill-benchmarks-mislead.md](why-naive-skill-benchmarks-mislead.md) §5)
applied to this project's own next instrument.

## CORRECTION — 2026-07-09 (competitive sweep ran AFTER the lock; gate amended)

The 2026-07-08 lock below was written **without a prior-art sweep** — a violation of the
instrument-gating rule this repo itself publishes
([why-naive-skill-benchmarks-mislead.md](why-naive-skill-benchmarks-mislead.md) §5:
"before building any harness/metric/oracle, run a prior-art sweep"). The sweep ran
2026-07-09. Two findings change the build emphasis, not the methodology:

1. **The re-aimed method is now field consensus, not differentiation.** Anthropic's
   skill-authoring best-practices doc officially prescribes baseline-without-skill
   evaluation and states no built-in runner exists (verified 2026-07-09). At least one
   actively-maintained OSS harness — `adewale/skill-eval-harness`, v0.5.1 (2026-07-08) —
   already ships paired with/without lift, materialized ablations with provenance,
   multi-turn subjects, deterministic/trace oracles, and permutation-test significance.
   The three decisions below stand (they converge with independent consensus, which is
   corroboration), but a v0.2 that merely implements them re-builds an existing tool.
2. **v0.2's build emphasis therefore shifts to what the sweep found nowhere else:**
   UNMEASURED as a first-class verdict, admissibility gating as the product, and
   clause-level directional drill-down as the differentiated secondary mode. Harness
   configuration itself becomes an admissibility condition (see amended table row) —
   published agentic-benchmark experience puts harness-induced variance at 10–20
   percentage points on identical model weights, larger than most skill effects.

Reflexive note: this correction is itself an instance of the gate's discipline applied
to the gate (the framework applies to its own instruments).

## The three re-aim decisions (locked direction, 2026-07-08)

1. **Unit inversion — skill-level first.** v0.1 makes single-clause ablation the primary
   unit. v0.2 makes **Full vs Null (whole-skill) the primary contrast**, run first;
   single-clause ablation becomes a drill-down executed only for skills whose skill-level
   contrast shows an effect. Rationale: the recurring real decision is "does this skill
   earn its slot," clause-level LOO is known-biased under redundancy (JoPA; skills are
   deliberately redundant), and the inversion collapses the multiplicity family from K
   clauses to 1 primary test per skill.
2. **Agentic subject layer.** v0.1's subject is a single-turn API call; skills live in
   multi-turn agentic tool-use sessions, and a clause can be inert single-shot while
   load-bearing deep in a session. v0.2 adds an agentic subject adapter (isolated
   per-condition config roots via `CLAUDE_CONFIG_DIR`, per-trial memory reset, credential
   sync, transient-retry) alongside the existing single-turn adapter. Style-shaped clauses
   may stay single-turn; behavior-shaped clauses require the agentic subject.
3. **Outcome-level Tier-1 oracles.** v0.1's mechanical scorers are stylometric
   (verbosity, hedging, structure, citations) — they can only validate style clauses.
   Agentic transcripts unlock deterministic outcome oracles: tests-pass, lint delta,
   diff size, tool-call count, turns, cost. These join the Tier-1 registry with the same
   offline-validity gate.

## Pre-registration fields (fill BEFORE any paid run)

| Field | Requirement |
|---|---|
| Pending decision | The concrete keep/cut/merge decision the result would change. No decision → no run. |
| Primary contrast | Full vs Null, skill-level, paired per task. |
| Task source | Real tasks from the skill's actual domain — NOT tasks selected because the skill addresses them (§3 of the findings doc). |
| Oracle set | Named Tier-1 outcome oracles + (if judge-graded) calibrated (judge, axis) pairs per the v0.1 calibration machinery. |
| MDE + sizing | From measured noise (CV ≈ 17.6% starting prior; re-measure per task class): state n × k and the minimum effect it can detect. |
| Stopping rule | Beta-Binomial sequential bounds (reuse `ablation/stopping.py`) with N_max stated. |
| Leak audit | Transcript grep protocol proving no task artifact contains the expected fix/answer or names the skill under test. |
| Harness pin | Exact subject-harness configuration (agent version, model id, permission mode, config-root contents, sandbox) recorded per trial and pinned across arms; an unpinned or drifted harness renders the trial's evidence inadmissible. |
| Differentiation vs field | Named check against existing tools (at minimum: Anthropic's prescribed method, `adewale/skill-eval-harness`, promptfoo, inspect_ai) stating what this run/feature produces that they cannot. "Nothing" → build interop or drop, don't rebuild. Added 2026-07-09; its absence from the original gate is how the 07-08 lock went stale in one day. |
| Budget | Per-run and total caps; spend written from actual usage (existing cost discipline). |

## What carries over from v0.1 unchanged

Evidence store (append-only, write-time admissibility snapshots), judge calibration +
position-swap + injection defense, hierarchical-Bayes aggregation with fallbacks, freeze/
regression machinery, dry-run-default CLI. The re-aim changes what is measured, not how
evidence is kept honest.
