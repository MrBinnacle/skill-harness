## Noise micro-run protocol (v1, 2026-07-09 — research-informed + pre-mortemed)

Replaces the informal "k=8, discordance primary" sketch after a targeted best-practices
sweep and an adversarial pre-mortem. Prior art (verified against sources): run-to-run
variance in agentic SWE evals is large and real (arXiv:2602.07150 — 60k SWE-bench-Verified
trajectories, single-run pass@1 varies 2.2–6.0pp, SD >1.5pp at temperature 0); repetition
counts of n=8–16 suffice for reliability estimates on structured tasks (arXiv:2512.06710);
and measuring the paired-correlation nuisance BEFORE sizing a paired test is exactly what
the paired-eval literature prescribes (arXiv:2605.30315 — unpaired sizing shortcuts are
~2× wrong in close comparisons). No published cross-arm discordance-rate protocol exists;
this one is registered here.

**Stage 0 — Null-only screen + cost calibration (≈$1–2, screen data never enters verdicts):**
3 Null-arm epochs on the candidate task. Kills three pre-mortem risks at once:
ceiling check (Null 3/3 pass → reject task, try next candidate), REAL per-epoch cost
(the $0.30/pair figure is anchored on a trivial k=1 file-creation POC — a genuine task
may cost 3–10×), and apparatus shakedown before paired spend.

**Stage 1 — Paired run:** k = 16 paired epochs if Stage-0 cost permits within budget,
else k = 8 floor. Hard cap $10 total including Stage 0. Launch config (each item traces
to a named pre-mortem failure mode): direct Anthropic API with pinned model id — NOT
OpenRouter (router backend heterogeneity inflates measured discordance; bridge reports
no cost, blinding the budget cap); `max_sandboxes` ≈ 3 (default would launch all
containers at once on Docker Desktop); `retry_on_error=1` (one errored epoch otherwise
voids the whole ingest — the write path refuses unpaired epoch sets); agent version
pinned at launch AND captured in-sandbox (`claude --version` into sample metadata —
a launch-parameter pin is a claim, not a measurement); oracle test files hash-checked
or re-copied pristine at scoring time (tests-pass is agent-tamperable in the sandbox);
leak audit = static grep + a fresh-context reviewer pass over every subject-visible
artifact + the registered post-run transcript grep (the known oracle-self-leak class
defeats grep alone).

**Analysis rules (pre-stated, before any data):**
- d is registered as a Jeffreys 95% INTERVAL, never a point estimate — at k=8–16 the
  interval spans several sizing-table rows and pretending otherwise writes noise into
  the REGISTERED field dressed as measurement.
- GO/NO-GO for the sized run: GO iff observed discordant epochs x ≥ ⌈0.5625·k⌉
  (k=16 → 9; k=8 → 5). Operating characteristic (exact binomial): P(GO | d=0.3) ≤ 6%,
  P(GO | d=0.8) ≥ 94%.
- Sizing uses the ~25th percentile of the d posterior, and treats even that as an
  UPPER BOUND on task-population d: the ceiling-guard task selection conditions on
  Null failures (selection toward high-discordance tasks). The sized run must restate
  this and size for a task MIXTURE (absorption is convex in d — sizing at the mean d
  is optimistic).
- Micro-run report template contains: d interval, discordance count, CV of
  tokens/turns/cost, apparatus notes. It contains NO win-direction field — k=8–16 is
  exactly the stopping rule's first-check region, and a "Full won 7/8, exploratory-only"
  sentence in project state would steer the REGISTERED thresholds it exists to set.
- Epoch independence basis (verified in inspect_ai 0.3.245 source): fresh sandbox per
  (sample, epoch); model-response cache is epoch-keyed by default. Residual: provider-side
  prompt-cache warm/cold differences load onto epoch-1-vs-rest cost/latency, so cost CV
  is read with that caveat.

**Detectability disclosure (RESOLVED at registration — operator-accepted values
decision, 2026-07-09):** under arm-independence the locked rule's 80%-power region
requires roughly Null pass ≤ ~0.3 AND Full pass ≥ ~0.8 — i.e., it detects
TRANSFORMATIVE skills only, and its FAIL/cut verdict fires readily on no-effect
skills. The operator explicitly accepted "keep only if transformative" as the keep/cut
bar; the locked constants stand unchanged. Any future re-opening of N_max/threshold
requires a dated correction block here first.

**Write path delivered (2026-07-09, `skill_harness.subject.ingest`):** paired
`.eval` logs now flow into the append-only evidence store — run + per-(arm, epoch)
samples (with pin JSON + fingerprint, migration 0500) + per-epoch Tier-1
`full_vs_null` outcome verdicts, harness-pin admissibility resolved at write time,
deterministic run id refusing re-ingest. Verified end-to-end against this first
paired shot's logs. Remaining before the sized run: pin extension (see Harness pin
row), noise micro-run, MDE/sizing, DRAFT→REGISTERED flip.
